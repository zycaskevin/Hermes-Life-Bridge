# HLB-004.6 — Doctor vNext & Route Lifecycle

**Status:** Implemented
**Canonical parent:** HLB-004.5 Hermes Compatibility Discovery

## Purpose

HLB Doctor now reports component-level health in human-readable form instead of a single opaque flag.

Primary components:

```text
Ingress
Cognition
Contact
Privacy
Compatibility
```

Each component reports:

```text
healthy
degraded
blocked
```

Overall status is:

```text
HEALTHY
DEGRADED
BLOCKED
```

Any blocked component blocks the overall report; otherwise any degraded component produces DEGRADED.

## Ingress

Doctor checks:

- Life Runtime Unix socket connectivity;
- Hermes Gateway hook registration/capability evidence;
- whether a real Gateway event has actually proven the hook.

A registered-but-never-observed hook is DEGRADED rather than silently assumed healthy.

## Cognition

Doctor checks:

- cognition service Unix socket;
- Hermes API health.

A failure in Cognition does not rewrite Ingress health, but it blocks the Cognition component explicitly.

## Contact

Doctor checks:

- contact service Unix socket;
- delivery-enabled state;
- Hermes send capability when delivery is enabled;
- learned route lifecycle state;
- unresolved `DELIVERY_UNKNOWN` operation count.

Any unresolved delivery-unknown operation is surfaced as a Contact safety blocker rather than hidden in the operation DB.

## Route lifecycle

Learned private routes now have explicit lifecycle status:

```text
UNKNOWN
FRESH
STALE
INVALID
```

Default freshness window:

```text
HLB_ROUTE_MAX_AGE_SECONDS=604800
```

(7 days.)

A new real Gateway message refreshes/replaces the learned route.

`RouteStore.invalidate()` explicitly invalidates a route. A later valid Gateway route replaces it and becomes fresh again.

A future-dated route beyond the clock-skew allowance is INVALID.

## Contact route safety

Contact resolution follows:

1. If a learned route exists and is FRESH, use it.
2. If a learned route is STALE or INVALID, block Contact; do not silently fall back.
3. If no learned route exists, an explicitly configured target may be used as the bootstrap/static policy.
4. The requested ContactIntent target must match the resolved exact target, `auto`, or the same allowed platform.
5. Learned route platform must remain inside the configured platform allowlist.

The resolved target is cryptographically bound into the Contact request hash. A route change therefore cannot silently redirect a previously reserved idempotent Contact operation.

## Privacy

Doctor checks:

- known forbidden Python/runtime representation bytes in operational DB/WAL/SHM/trace files;
- private-file mode for RouteStore, operation DB, Contact DB, compatibility report, and compatibility evidence.

Doctor itself never prints the exact learned route or configured private target. Only the platform and route status are exposed.

## Backward-compatible low-level fields

Existing automation may still read:

```text
runtime_socket
cognition_socket
contact_socket
hermes_api
trace
```

These low-level fields are retained, while `components` provides the new human-readable health model.

## Hard invariants

1. Doctor never echoes an exact private route.
2. Stale learned route cannot silently deliver.
3. Invalid learned route cannot silently deliver.
4. New real route refreshes route lifecycle.
5. Contact idempotency binds the resolved route hash.
6. `DELIVERY_UNKNOWN` is visible as a Contact safety blocker.
7. Representation-boundary violation blocks Privacy health.
8. Private operational file mode other than 0600 blocks Privacy health.
9. One component failure does not falsify another component's status.
10. Human-readable component messages accompany machine-readable status.
