# HLB-004.7 — Failure Injection & Automatic Recovery

**Status:** Implemented
**Canonical parent:** HLB-004.6 Doctor vNext & Route Lifecycle

## Purpose

HLB-004.7 deliberately breaks each critical dependency and verifies that HLB either recovers automatically or fails closed without duplicate external side effects.

## Ingress durability

Gateway/CLI Percepts now use a durable, privacy-minimized outbox in the shared OperationStore.

The outbox stores only the canonical Runtime Percept envelope:

```text
event_id
life_did
source_body_id
modality
observed_at
payload_ref
salience_hint
idempotency_key
schema_version
```

It does **not** store raw user message text, chat id, thread id, exact contact target, or arbitrary Hermes runtime objects.

Reservation of the operation and Percept envelope is atomic in one SQLite transaction.

## OperationStore schema v2

Schema version `2` adds:

```text
percept_outbox
```

Existing schema-v1 operation databases migrate in place without losing prior Cognition/Contact operations.

Newer-than-supported schemas still fail closed.

## Runtime restart recovery

The Percept path now performs:

```text
normalize
↓
durable outbox reserve
↓
PREPARED → IN_FLIGHT
↓
Runtime socket send
```

If Runtime is down or the ACK is lost:

```text
IN_FLIGHT → FAILED_SAFE → RETRY_WAIT
```

Percept replay is safe because the canonical Runtime idempotency key is unchanged.

If Runtime actually persisted the Percept but HLB lost the ACK, replay receives/behaves as a duplicate and Runtime state advances only once.

## Percept recovery daemon

New systemd service:

```text
hermes-life-percept-recovery.service
```

runs the bounded retry pump every 0.5 seconds.

It never stores or reconstructs raw user message text. It only replays the content-free canonical Percept envelope.

All HLB reliability services now use:

```text
Restart=on-failure
RestartSec=1
StartLimitIntervalSec=0
```

so repeated temporary process failures do not permanently disable recovery.

## Cognition runtime reliability

Cognition execution is now wired to the HLB-004.3 durable retry engine.

For transient Hermes API failures:

```text
attempt 1 → FAILED_SAFE
attempt 2 → FAILED_SAFE
attempt 3 → success or EXHAUSTED
```

Cognition remains capped at three total attempts.

The service checks for an accepted CognitiveReceipt before starting a retry. If the process crashes after persisting the receipt but before marking the operation complete, startup reconciliation marks the operation complete without recomputing.

Cognition operational storage still excludes the raw instruction from its task cache.

## Failure cases injected

The suite deliberately covers:

- Life Runtime unavailable before send;
- Runtime accepted Percept but ACK was lost;
- crash between durable reservation and Runtime send;
- crash after Runtime persistence before HLB ACK handling;
- duplicate Percept after HLB restart;
- Hermes API transient 500-equivalent failure;
- persistent Hermes API failure through retry exhaustion;
- Cognition receipt persisted before operation-complete crash;
- Contact provider timeout / unknown outcome (HLB-004.4 suite);
- Contact receipt persisted before operation-complete crash (HLB-004.4 suite);
- corrupt OperationStore SQLite file;
- stale/invalid RouteStore;
- repeated plugin registration/reload;
- systemd service restart contract;
- OperationStore v1→v2 migration.

## Result rules

Each injected fault must result in one of:

```text
automatic recovery
bounded deferred retry
explicit exhausted state
explicit blocked/unknown state
```

Never:

```text
blind Contact resend
unbounded retry
raw-message persistence
silent route guess
silent DB/schema downgrade
```

## Hard invariants validated

1. Runtime disappearance does not lose a content-free Percept permanently during the retry window.
2. Runtime ACK loss does not advance Runtime state twice.
3. Crash before send is recoverable from durable outbox.
4. Crash after Runtime persistence is idempotently recoverable.
5. Duplicate Percept after restart does not call Runtime again after local completion.
6. Cognition transient failures retry within the bounded policy.
7. Cognition persistent failure terminates at EXHAUSTED.
8. Persisted CognitiveReceipt prevents post-crash recomputation.
9. Contact unknown delivery never enters automatic retry.
10. Corrupt operational DB fails closed.
11. Invalid route stays blocked.
12. Plugin reload remains observer-safe.
13. Recovery services restart automatically.
14. Schema migration preserves prior operation state.
