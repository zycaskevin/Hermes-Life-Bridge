# HLB-003.2 — Contact Trace Privacy Hotfix

HLB-003.1 proved the real Feishu delivery path, but post-send operational trace still exposed
the canonical target/chat_id. Code review also found that ContactStore could persist the exact
target outside the private RouteStore.

HLB-003.2 changes no routing, ContactDecision, or provider behavior.

Privacy contract:
- exact platform/chat/thread route exists only in mode-0600 RouteStore;
- normal trace strips target/chat/thread identity keys;
- contact stages emit `target_platform` + `target_redacted=true` only;
- failure trace stores error type + one-way fingerprint, never raw exception detail;
- ContactStore persists target platform + target hash, not exact route;
- startup migration redacts HLB-003.1 rows and uses secure_delete + VACUUM + WAL truncate;
- duplicate delivery responses reconstruct the exact target only in memory from the incoming
  authorized ContactIntent and do not invoke the provider again.
